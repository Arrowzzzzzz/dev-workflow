# 场景 B：单点修 bug 工作流

> 本手册在总纲（SKILL.md）底线之上执行：确认闸门、基于证据、实施纪律、高风险二次确认、测试失败修正规则、回归测试硬门禁均按总纲执行，本手册不再重复展开。
> 边界：本场景适用于用户**已指出具体 bug / 报错 / 异常现象**的轻量修复。若问题尚未定位、需要系统性找问题 → 场景 C（audit-fix.md）；若修复过程中发现更深层问题 → 向用户说明后切换到场景 C。若修复范围扩大到新功能实现 → 切换到场景 A（new-feature.md）。

【强制工作流，任何步骤不得跳过】任何实施动作都必须发生在用户确认之后；未经确认的修复方案只停留在讨论层。

## 第 1 步：复现与信息收集

- 目标：把问题变成可复现、可验证的事实，而非模糊描述；
- 收集：复现路径（操作步骤）、触发条件、报错信息 / 堆栈 / 日志、影响范围（哪些用户 / 功能受影响）、出现频率；
- 能接触代码与环境时，先尝试按用户描述复现；
- 信息不足时，按下方提问清单编号一次问全：

**报障信息提问清单**：
1. 具体操作步骤与触发条件？
2. 期望行为 vs 实际行为？
3. 报错信息 / 日志 / 截图（如有）？
4. 影响范围（单个页面 / 整个功能 / 所有用户）与出现频率？
5. 最近是否有相关改动（部署、配置、依赖、数据变更）？

## 第 2 步：根因定位

- 基于证据定位真正根因（root cause），而非表面现象；结论引用具体文件与行号；
- 严格区分两类结论：
  - **确定的根因**：有明确证据（逻辑矛盾、必然报错、契约不一致）；
  - **假设**：可能的原因但证据不足，必须标注「假设」并向用户求证后再继续；
- 定位结论无法收敛时：向用户说明已排查的路径与下一步建议，必要时切换场景 C 做系统排查。

## 第 3 步：最小修复方案

按 `assets/PLAN_TEMPLATE.md` 的精简版输出（复用同一模板，聚焦以下字段）：

- 根因总结（确定 / 假设）；
- 改动文件清单（文件 | 改动内容 | 理由 | 风险）；
- 修复方式与关键步骤（最小改动、修根因而非掩盖症状）；
- 影响面与兼容性；
- 测试计划：**原 bug 场景反证** + 受影响路径回归 + 相关自动化用例；
- 待确认项清单（编号）。

多方案时给出对比与推荐及理由。

输出方案后，先对照根因与需求做一次自我审查（见 `references/self-review.md`）——检查最小改动是否修根因、原 bug 场景是否可反证，再进入第 3.5 步。

### 第 3.5 步：跨角色沟通评审（修改代码之前强制）

- 按 `references/agents.md` 第三节执行（轻量版）：判定受影响角色 → 各角色加载知识库 → 按关注点矩阵输出意见 → 汇总《协作纪要》；
- 协作纪要与修复方案一并提交用户确认；角色间分歧由用户裁决后更新方案再继续。

## 第 4 步：确认后修复

- 输出方案后**立即停止**，用"我想这样修：[方案 + 协作纪要]，是否确认？"形式询问；
- 未收到明确肯定前，禁止改动任何代码；
- 高风险项（总纲第 4 条清单）逐项单独二次确认；
- **角色与规范**：按 `references/agents.md` 分配执行角色并加载角色知识（按 config.yaml 声明角色与模型，未配置声明平台默认）；加载 `references/coding-standards.md` 相关章节逐项对照；
- 按总纲第 3 条实施纪律执行（复用优先、最小改动、不顺手重构、保持兼容、新依赖先确认）。

## 第 5 步：回归测试验证（硬门禁）

- 按总纲「自测与回归规范」执行：重启判定（涉及后端 / 配置 / 依赖变更必须重启后再测）；
- **回归测试硬门禁**（总纲第 6 条），至少覆盖：
  - 原 bug 场景反证：按第 1 步的复现路径验证问题已消失；
  - 受影响路径回归：根因定位时梳理的关联路径逐一验证；
  - 相关自动化用例全部通过；
- 全部通过才允许宣布修复完成；失败按总纲第 5 条修正规则处理；
- 无自动化测试时：列出手动验证步骤与预期结果，逐条执行并如实记录。

## 第 6 步：形成更新记录与交接联动

- 按 `assets/UPDATE_LOG.md` 统一模板写入（类型填「Bug 修复」，背景 / 根因必填 root cause），新记录置顶；
- 写入后与本次实际改动逐条核对；
- 项目已有交接文档集时：查影响映射表更新受影响章节（如「已知问题」分册移除已修复项），并在 UPDATE_LOG 记录；受影响的图（图清单表）与角色知识文件（`.devflow/agents/`）同步增量更新；
- 输出简短完成报告：根因、改动摘要、回归结果；交付前对照原 bug 场景与需求自我审查一次（见 `references/self-review.md`）。

## 自检清单

- [ ] 已按提问清单收集信息并复现问题，无未确认的事实
- [ ] 根因基于证据（文件+行号），确定 / 假设已区分，假设已求证
- [ ] 修复方案最小化，未顺手重构；方案与修复已对照根因 / 需求自我审查（见 self-review.md）
- [ ] 跨角色沟通评审已完成，协作纪要随方案确认
- [ ] 已获用户明确确认，高风险项已二次确认；执行角色已分配并加载角色知识
- [ ] coding-standards 相关检查项已对照，强制项满足
- [ ] 原 bug 场景反证通过，受影响路径回归通过，相关自动化用例全部通过
- [ ] UPDATE_LOG.md 已写入并与改动一致；交接文档 / 图表 / 角色知识文件已联动更新
