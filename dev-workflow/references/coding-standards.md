# 编码规范与实施纪律手册

> 本手册在总纲（SKILL.md）底线之上执行。场景 A（阶段 5）、场景 B（第 4 步）、场景 C（修复阶段）实施代码时**必须加载本手册**，按项目实际技术栈裁剪后逐项对照；裁剪项需向用户说明理由。
> 检查项按「强制 / 建议」标注：**强制项不满足不得宣称任务完成**。项目已有团队编码规范时，以项目规范为准，本手册仅补缺。

## 1. 编码规范与自审清单

- 命名（强制）：函数 / 变量语义化，沿用项目既有风格——先读现有代码确定风格，不另起炉灶；
- 注释（强制）：写"为什么而非做什么"；公开接口 / 复杂逻辑必须有注释；
- 错误处理（强制）：异常不静默吞掉（空 catch 须注释原因）；错误信息可定位（含上下文）；错误码沿用项目约定，不新造；
- 日志（建议）：关键路径有日志、级别正确、不含敏感信息；
- **提交前自审清单**（强制逐项过）：
  - [ ] 无调试代码（console.log / print / 断点 / 测试桩）
  - [ ] 无硬编码密钥 / 令牌 / 密码
  - [ ] 命名与注释清晰，无死代码、无大段注释掉的旧代码
  - [ ] 错误路径已处理，异常不吞
  - [ ] 未引入与本次任务无关的改动（diff 干净）

## 2. 安全编码内建

- 输入校验（强制）：所有外部输入（参数 / 表单 / 文件 / 请求头）白名单校验；服务端校验优先，不信任前端校验；
- 注入防护（强制）：SQL 用参数化 / ORM；XSS 输出转义，危险 sink（innerHTML / eval）禁用或严格过滤；命令执行避免字符串拼接；
- 敏感信息（强制）：密钥 / 令牌不硬编码、不明文入库、不打日志、不进 URL；加密用标准库（bcrypt / AES-GCM 等），不自研算法；
- 越权检查（强制）：按 ID 取数据先校验归属（水平 / 垂直权限）；前端隐藏不替代后端拦截。

## 3. 接口 / API 设计规范

- RESTful（建议）：名词复数资源、HTTP 方法语义正确、状态变更用 PATCH、路径带版本前缀（沿用项目实际约定）；
- 参数校验（强制）：必填 / 格式 / 范围服务端校验，错误信息明确可行动；
- 错误码（强制）：沿用项目统一错误码与返回结构（code / message / data），不新造；
- 分页（强制）：列表必分页（page / size），大结果集必须有限制；
- 幂等（建议）：写接口考虑重试安全（幂等键 / 唯一约束），异步任务返回任务 ID 并提供查询接口。

## 4. 数据库变更规范

- 结构变更（强制）走迁移脚本（Flyway / Liquibase / 项目既有工具），禁止"手改库"作为发布方式；
- 新增字段考虑默认值 / 可空与旧数据兼容；删除列先标记废弃、保留兼容期再删；
- 索引（强制）：新查询按访问模式评估索引；唯一约束与业务规则一致；
- 变更兼容（强制）：旧版本代码能读新结构（至少一个发布周期）。

## 5. 可观测性内建

- 关键路径日志埋点（强制）：入口参数（脱敏）、关键分支、耗时、出口结果；
- 指标（建议）：接口耗时 / 错误率、队列深度、缓存命中（沿用项目监控体系）；
- 串联排查（建议）：错误日志含请求标识（trace id / request id）。

## 6. 性能内建

- N+1（强制）：批量查询 / join / 预加载；循环内禁止查库 / 调接口；
- 批量操作（建议）：批处理、批量写；
- 缓存（建议）：热点数据缓存策略与失效时机明确；避免缓存穿透 / 雪崩；
- 大数据量（强制）：分页、流式处理；前端大列表虚拟化。

## 7. 破坏性变更与兼容管理

- 破坏性变更（强制）先评估影响面（调用方清单），方案中说明迁移步骤；
- deprecated 标记（强制）：注释 / 文档标注废弃与替换方案，保留兼容期；
- 版本策略（建议）：接口版本化；数据迁移向前兼容；
- 回滚预案（强制）：变更方案附回滚步骤。

## 8. 依赖管理规范

- 锁文件（强制）随代码提交（package-lock / yarn.lock / pom 版本锁定等）；
- 新依赖（强制）先经确认闸门（总纲第 3 条）：选成熟、稳定、社区活跃的库，说明理由与替代方案；
- 升级（强制）：先看 changelog / breaking changes，升级后跑回归；已知漏洞依赖优先修复；
- 去重（强制）：不引入功能重复的库（复用优先）。

## 9. 重构安全网

- 重构前（强制）先补特性测试（characterization tests）锁定现有行为——尤其是无测试的遗留代码；
- 小步重构（强制）：每步保持测试全绿；先行为不变，再结构调整；
- 不顺手重构（强制）：与本次任务无关的重构单独提案，不夹带。

## 10. 配置与密钥管理

- 环境差异（强制）走环境变量 / 配置分层，不硬编码环境相关值（域名 / 端口 / 路径）；
- 密钥（强制）走密钥管理 / 环境注入，不入代码、不入版本库（.env.example 只放占位）；
- 配置变更（强制）与代码变更同流程（确认闸门 + 回归验证）。

## 11. 国际化约定

- 文案（强制，多语言项目）统一走 i18n 资源文件，键名规范（模块.语义），不硬编码页面文案；
- 复用已有键（建议），避免同义多键；文案变更同步各语言文件；缺失回退策略明确；
- 日期 / 金额 / 时区格式化（强制）走统一工具，不自行拼格式。

## 12. 文档生成联动

- docstring（建议）：公开函数 / 接口写参数 / 返回 / 异常说明，风格沿用项目约定；
- API 文档（强制，如项目有）随接口变更同步更新；
- README / 交接文档（强制）：受影响章节按保鲜联动更新（总纲）。
