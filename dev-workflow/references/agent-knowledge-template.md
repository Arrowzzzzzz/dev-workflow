# 角色知识库模板与生成流程

> 配套 agents.md。角色知识库存于项目 `.devflow/agents/`，每角色一个文件；模型配置见 `.devflow/agents/config.yaml`（模板见本技能 `assets/agent-config-template.yaml`）。

## 一、知识文件结构模板（.devflow/agents/<role>.md）

```
# <角色名> 知识库（示例：前端 UI）

> 维护：随项目变更增量更新（保鲜联动）。最后更新：YYYY-MM-DD。

## 1. 角色定位与边界
<该角色在本项目的职责范围、明确不做什么>

## 2. 技术栈与版本
| 类别 | 技术 | 版本 | 说明 |
|---|---|---|---|
| 框架 | Vue 3 | 3.x | ... |

## 3. 目录结构与分层约定
<相关目录职责、文件放哪、路由 / 状态 / 组件组织约定>

## 4. 已实现组件 / 模块清单
| 名称 | 位置 | 能力 | 复用要点 |
|---|---|---|---|

## 5. 约定与命名
<命名、代码风格、错误处理、日志、国际化等约定（指向 coding-standards.md 中适用项）>
```

## 二、生成流程（角色首次使用时）

1. 触发：某角色首次执行任务、知识文件不存在或明显过期；
2. **扫描项目**：技术栈配置文件（package.json / pom.xml / requirements.txt 等）、目录结构、已实现模块、UPDATE_LOG、交接文档（场景 E 产出）中该角色相关分册；
3. 生成知识文件草稿：按第一节模板填写，扫描不到的信息标注 `【待确认】`；
4. 提交用户确认（确认闸门），确认后落盘 `.devflow/agents/<role>.md`；
5. 无代码可读时：按模板向用户提问收集信息（编号一次问全）。

## 三、增量更新流程（保鲜联动）

- A/B/C 每次变更完成后：按影响映射表 + 角色归属，判定受影响的角色知识文件；
- 增量更新受影响小节（技术栈变更 → §2；新组件 → §4；新契约 → §7；踩坑 → §8），不整篇重写；
- 更新后在 UPDATE_LOG 记录知识库同步情况；
- 每次使用某角色执行任务前也须核验其知识文件与项目现状一致（不只依赖变更后联动）；发现过期或明显不符，先增量更新再动手（使用规则见 agents.md）。

## 四、模型配置

- 复制本技能 `assets/agent-config-template.yaml` 到项目 `.devflow/agents/config.yaml`（技能调用时缺失会自动生成）；
- 结构为 `models.<角色>.<工具>`（五工具：zcode / opencode / dsh / codex / cc）；留空 "" 或 inherit = 跟随主会话当前模型；模板不预置任何具体模型，由用户手动填写；
- config.yaml 变更后按 agents.md 5.6 自动同步到各工具配置（快照类文件可用可选脚本 `assets/adapters/sync.py` 重生成）；
- 技能执行时按 agents.md 角色路由声明角色与模型，实际切换由运行平台执行。
