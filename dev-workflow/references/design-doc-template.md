## 各章编写要点

### 文档概述

- **文档目的**:一句话说明文档定位——作为开发、测试、运维的唯一依据,新成员阅读后可直接参与开发。
- **读者对象**:列出目标读者角色。
- **修订历史**:表格,列为 `版本 | 日期 | 修订内容 | 作者`。每次修订必须新增一行,版本号递增。
- **术语说明**:指向附录术语表。

### 1. 项目概述

- **1.1 背景与痛点**:当前系统/流程存在的具体问题,量化描述(如数据规模、效率损失)。
- **1.2 建设目标**:与痛点一一对应的目标,可衡量。
- **1.3 项目范围**:明确划分一期功能清单与二期预留,避免范围蔓延。

### 2. 系统边界与角色定义

- **2.1 系统端侧**:列出所有客户端形态(Web 管理后台、H5、OpenAPI 等)及使用者、技术选型;未来扩展端侧单独标注。
- **2.2 角色与权限矩阵**:表格,列为 `角色 | 角色编码 | 核心权限描述`。角色编码需与后续权限设计、数据库初始化数据一致。

### 3. 功能模块清单(含权限标识)

表格,列为 `一级模块 | 二级功能 | 功能详细描述 | 对应权限标识`。

- 权限标识采用统一格式,如 `模块:资源:操作`(示例:`emp:list`、`system:user:add`)。
- 后端自动触发、无需权限控制的功能在权限标识列注明"后端自动触发"。
- 本章权限标识是全文权限体系的唯一来源,第 8 章、第 11 章必须与之一致。

### 4. 非功能性需求

分四小节,指标必须量化:

- **4.1 性能**:核心接口 P95/P99 响应时间、批量任务耗时上限、缓存命中率等。
- **4.2 可用性**:可用性目标(如 99.9%)、部署冗余方式(多节点、主从、哨兵)、备份策略。
- **4.3 安全性**:密码/敏感字段加密算法、密钥管理方式、防注入/XSS/CSRF、脱敏、限流。
- **4.4 可扩展性与可维护性**:模块化策略、接口版本化(如 `/api/v1/`)、统一错误码与全局异常处理。

### 5. 技术架构设计

- **5.1 架构全景图**:按 C4 分层绘制(图表规范见 `references/diagrams.md`):L1 系统上下文图(本系统与外部用户/系统)、L2 容器图(客户端 → 网关/反向代理 → 应用集群 → 存储(数据库、缓存、对象存储)→ 外部依赖(邮件、调度、消息推送)的完整链路),L3 组件图按需(核心容器内部模块);Mermaid C4 语法为主,复杂部署图用 PlantUML 备选;图源文件按规范落盘并登记图清单表。
- **5.2 前端技术栈**:框架、构建工具、UI 库、状态管理、路由及关键插件,写明版本。
- **5.3 后端技术栈**:框架、ORM、安全组件、文档工具、监控组件,写明版本。
- **5.4 项目代码结构**:目录树,注释每个目录职责;后端按 common/framework/modules 分层,业务模块独立分包。
- **5.5 开发环境一键启动**:提供完整 `docker-compose.yml`(数据库、缓存、对象存储、前后端),并说明启动命令与访问入口。

### 6. 核心业务流程与逻辑

选取 3–5 个最核心的流程,按编号步骤描述,覆盖:

- 认证登录流程(含验证码、失败锁定、双 Token 刷新机制)
- 核心实体的创建流程(含唯一性校验、加密存储、自动编号、异步日志)
- 权限校验流程(Token 解析 → 上下文注入 → 方法级注解 → 前端路由/按钮控制)
- 异步处理与分布式锁(导入导出、定时任务的并发控制)

关键算法(如编号生成器)附实际技术栈的代码示例。

### 7. 核心状态机与约束规则

- **状态转换**:枚举各状态值及允许的转换路径,注明后端强制校验。
- **删除约束**:逻辑删除策略、级联约束(有下级/被引用时禁止删除)。
- **其他不变量**:如"用户至少一个角色"、"禁用后 Token 立即入黑名单"等系统级约束。

### 8. 权限与安全设计

- **8.1 认证与授权**:认证方案(如 JWT 签名算法)、密码加密、敏感字段加密与密钥注入方式、权限模型(如 RBAC:用户→角色→菜单/按钮)、数据权限预留字段。
- **8.2 脱敏规则**:逐字段列出脱敏格式(证件号、手机号、姓名等)及实现方式。
- **8.3 防攻击**:验证码、接口限流规则(维度+阈值)、安全响应头。
- **8.4 核心安全配置代码示例**:基于实际框架给出关键配置类。

### 9. 全局异常处理与错误码规范

- **9.1 统一返回体**:JSON 结构示例,含 `code`/`message`/`data`/`timestamp`。
- **9.2 错误码枚举**:表格,列为 `错误码 | 描述`。通用码沿用 HTTP 语义(200/400/401/403/404/429/500),业务码从 10001 起按模块分段。说明全局异常处理与国际化消息机制。

### 10. 数据库设计

- **10.1 ER 图**:Mermaid `erDiagram`,覆盖全部核心表及关系。
- **10.2 核心表详细设计**:每表一个小节,表格列为 `字段 | 类型 | 说明`。通用要求:主键、唯一键标注;审计字段(create_by/create_time/update_by/update_time);逻辑删除字段;敏感字段注明加密方式。说明初始化数据内容(管理员账号、基础角色、预置菜单)。
- **10.3 索引优化建议**:按表列出组合索引及适用查询场景。

### 11. 核心接口文档

- 基础约定:Base URL、认证头、统一返回格式、在线文档地址。
- 按模块分小节列出接口:`方法 路径 - 说明(关键参数)`。
- RESTful 风格:名词复数、状态变更用 PATCH、异步任务返回任务 ID 并提供进度查询接口。
- 接口的权限要求须与第 3 章权限标识对应。

### 12. 日志与监控设计

- **操作日志**:注解 + AOP 实现方式,记录内容(参数、结果、耗时),异步写入。
- **登录日志**:记录时机与字段。
- **异常监控**:错误告警通道(如钉钉/邮件)、指标监控栈(如 Prometheus + Grafana)、关键业务指标埋点。

### 13. 定时任务与异步处理

- 线程池配置代码(核心/最大线程数、队列容量、拒绝策略)。
- 定时任务清单:任务名、执行频率、逻辑摘要。
- 分布式环境下的单点执行保障方式(分布式锁)。

### 14. 数据初始化与迁移策略

- 初始化脚本内容清单(建表、索引、初始账号与密码策略、预置数据)。
- 旧系统数据迁移路径(脚本 → 导入接口),注明字段映射与加密处理。

### 15. 部署与运维

- **环境要求**:各组件最低版本。
- **手工部署步骤**:数据库初始化 → 后端打包运行 → 前端构建 → 反向代理配置。
- **容器化/K8s 部署**(如适用):滚动更新、健康检查、配置注入方式。
- **数据库备份**:备份脚本与频率。

### 16. 测试方案与验收标准

- **测试策略**:单元测试(覆盖率目标+框架)、集成测试、UI 自动化、性能测试(并发数+指标)。
- **关键测试用例**:表格,列为 `ID | 场景 | 步骤 | 预期`,覆盖核心正向流程与关键异常(锁定、重复、约束拦截)。

### 17. 开发规范与最佳实践

- **命名规范**:类/方法/数据库字段/URL/Git 分支。
- **注释与文档**:公开方法文档注释、"注释为什么而非做什么"、数据库列 COMMENT。
- **Code Review 清单**:复选框列表(接口一致性、参数校验、加密脱敏、日志、测试、SQL 安全、N+1)。
- **前端组件封装建议**:通用表格组件、权限指令等。

### 18. 国际化与多语言支持(可选)

前端语言包组织、UI 库国际化配置、语言持久化与请求头传递;后端资源文件、异常消息与邮件模板的国际化机制。无国际化需求的项目删除本章。

### 19. CI/CD 与自动化运维

- Pipeline 示例(检出 → 构建 → 测试 → 镜像构建推送 → 部署)。
- 回滚策略:镜像版本化、数据库变更管理工具(如 Flyway)的向下兼容要求。

### 20. 常见问题与排错指南(FAQ)

编号列表,每条格式:**现象** → 排查/解决方法。覆盖启动、认证、导入导出、中间件连接、前端路由、跨域等高频问题,至少 8 条。

### 21. 系统扩展与二期预留

- **数据库预留**:二期功能的表结构草案。
- **接口与前端预留**:预置菜单/权限标识、占位组件、预留注解。
- **架构扩展**:异步方案升级路径、新端侧接入方式。

### 附录

- **附录A 术语表**:文档中出现的专业术语逐条解释。
- **附录B 代码生成器模板**(如适用):基于实际 ORM 的生成器配置示例。
- **附录C 通用组件设计思路**(如适用)。
- **附录D 本地开发快速启动步骤**:从零到可登录访问的编号步骤,含默认账号与各控制台地址。

## 全文格式约定

- 图:按 `references/diagrams.md` 执行——架构图用 C4 分层(Mermaid C4 语法为主,复杂部署图用 PlantUML 备选),ER 图用 Mermaid `erDiagram`;图源文件落盘 `docs/architecture/diagrams/` 并登记图清单表。
- 表:统一 Markdown 表格,表头与上述各章约定一致。
- 代码:标注语言的围栏代码块,必须基于项目实际技术栈。
- 待定内容统一标注 `【待确认】`,并在文末汇总清单。
