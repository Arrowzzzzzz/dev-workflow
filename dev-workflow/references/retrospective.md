# 场景 G：回顾性工作流（复盘 / 回顾 / 总结）

> 本手册在总纲（SKILL.md）底线之上执行：基于证据（不臆造）、提问规范均按总纲执行，本手册不再重复展开。
> 定位：四类回顾能力——①变更后即时回顾（自动轻量）②变更 / 迭代复盘 ③事故复盘 post-mortem ④项目健康回顾。
> 触发规则：①随场景 A/B/C 完成自动附带；②③④由用户主动发起（"回顾一下…""复盘…""做个体检"）。回顾结论必须基于真实材料（UPDATE_LOG、git 历史、测试记录、事故信息），不得编造。

## 一、选定复盘类型

- 用户表述包含"这周 / 这个迭代 / 这段时间 / 总结" → ②变更 / 迭代复盘；
- 用户表述包含"事故 / 故障 / 挂了 / 出了什么问题" → ③事故复盘；
- 用户表述包含"项目健康 / 技术债 / 体检 / 质量盘点" → ④项目健康回顾；
- 大变更刚完成且用户未指定 → ①变更后即时回顾（随完成报告附上，见场景 A/B 手册）。

## 二、采集材料

| 复盘类型 | 主要材料 |
|---|---|
| ②变更 / 迭代复盘 | `UPDATE_LOG.md`、git 提交历史（时间范围按用户指定）、测试记录、交付清单 |
| ③事故复盘 | 事故时间线（用户提供 / 日志）、相关 UPDATE_LOG 与代码、监控告警记录、事后处置记录 |
| ④项目健康回顾 | 代码库扫描（可复用场景 C 的 11 维度做体检）、依赖清单与版本、UPDATE_LOG、测试覆盖报告、交接文档「已知问题」分册 |

信息不足时编号提问一次问全（时间范围、事故起止时间、是否涉及线上数据等）。

## 三、输出报告（按对应模板）

### ① 变更后即时回顾（3–5 行，附在完成报告后）

```
## 即时回顾
- 与方案的偏差：<有/无，若有说明原因>
- 测试与回归情况：<覆盖了什么、有无遗漏>
- 可沉淀经验：<一句话，无则写「无」>
```

### ② 变更 / 迭代复盘模板

```
# <时间段>变更/迭代复盘

## 完成情况
| 变更/事项 | 目标 | 结果 | 来源(UPDATE_LOG/commit) |
|---|---|---|---|

## 效果评估
<目标达成度；用户 / 业务反馈（如有）>

## 问题与教训
1. <问题> → 根因：<…> → 教训：<…>

## 改进项
| 改进项 | 行动 | 负责人/时机 | 状态 |
|---|---|---|---|

## 风险提示
<延续到下一周期的风险与注意事项>
```

### ③ 事故复盘 post-mortem 模板

```
# <事故名>复盘

## 时间线
| 时间 | 事件 | 处置动作 |
|---|---|---|

## 影响面
<受影响功能、用户、数据、持续时间>

## 根因分析
<直接原因 + 深层原因（为什么防御机制未生效）；多重根因并列，不归咎于个人——复盘目标是改进系统而非追责>

## 短期补救
| 措施 | 状态 |
|---|---|

## 长期改进
| 措施 | 优先级 | 负责人/时机 |
|---|---|---|

## 经验沉淀
<预防同类问题的可复用规则 / 检查项（可建议并入交接文档「已知问题」分册）>
```

### ④ 项目健康回顾模板

```
# 项目健康回顾

## 总体评分
<按维度打分 + 一句话总评>

## 技术债清单
| 债 | 位置 | 影响 | 偿还建议 | 优先级 |
|---|---|---|---|---|

## 质量与测试
<测试覆盖、未补测缺口、回归清单健康度>

## 安全与合规
<待处理安全项、依赖漏洞、密钥管理>

## 依赖健康
| 依赖 | 当前版本 | 最新版本 | 风险 |
|---|---|---|---|

## 风险清单与建议
| 风险 | 影响 | 建议行动 |
|---|---|---|
```

## 四、确认落点与记录

- ①即时回顾：附在完成报告中，不单独落盘；
- ②③④：向用户确认落点——写入 `UPDATE_LOG.md`（新记录置顶，类型填「其他」并注明复盘类型）或独立复盘文档（建议 `docs/retro/<YYYY-MM-DD>-<标题>.md`）；
- 落盘后与用户确认报告内容无异议；事故复盘如产出长期改进项，同步更新交接文档「已知问题 / 演进方向」分册（若存在）。

## 自检清单

- [ ] 复盘类型判定正确，材料基于真实记录，无编造
- [ ] 时间范围 / 事故信息等缺失项已向用户确认
- [ ] 报告按对应模板输出，改进项有行动与时机
- [ ] 落点已确认并完成写入；相关文档联动已完成
